# Frontend API Boundary

Frontend application code must consume the API through generated files in `apps/fe/src/openapi` for the web app and `apps/mobile/api` for the mobile app.

Use generated modules such as:

- `@/openapi/<domain>/<domain>.queries`
- `@/openapi/<domain>/<domain>.models`
- `@/openapi/queryModules`

Mobile code should use its generated modules from `apps/mobile/api`.

For generated mutations, pass invalidation through the mutation options instead of importing `queryClient` or calling `invalidateQueries` with generated query keys. The current module is invalidated by default through `invalidateCurrentModule: true`; invalidate dependent modules explicitly with `invalidateModules: [QueryModule.someModule]`.

After mutations, derive follow-up UI state from canonical API response or query state instead of leaving action controls unchanged. Disable duplicate submissions when the API state already represents a pending or completed action, and surface mutation errors through the default generated-client error handler or a feature-specific message.

Do not import API contracts, routers, DB schemas, DB row types, repositories, or seed data into frontend features. In particular, avoid imports from:

- `~/orpc/**`
- `~/db/**`
- `packages/fake-be/src/orpc/**`
- `packages/fake-be/src/db/**`

Do not share Zod schemas or TypeScript types from the fake backend with the frontend. If the frontend needs a type, schema, query, mutation, ACL module, or request body shape, expose it through the oRPC contract, regenerate OpenAPI, and consume the generated `@/openapi` output.

Exception: template-only developer controls may import fake-backend helpers directly when exposing them through OpenAPI would describe behavior the real backend should not implement. The reset seed data button may import `resetStore` from `~/db/store` because it exists only to reset browser seed data during local development.

`apps/fe/src/openapi` and `apps/mobile/api` are generated by `@povio/openapi-codegen-cli` from `packages/fake-be/openapi.generated.json`. Do not hand-edit generated OpenAPI client files.

When API contracts change:

1. Update `packages/fake-be/src/orpc` models, contracts, routers, and `meta.bl`.
2. Run `bun openapi:gen`.
3. Update frontend code to use the regenerated queries and models.

The browser fake-backend adapter is infrastructure only. Do not copy its direct oRPC access pattern into feature code.
